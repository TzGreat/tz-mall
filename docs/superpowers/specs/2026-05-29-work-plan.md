# TZ-Mall 工作规划 - 低耦合到高耦合

> 创建时间：2026-05-29
> 基于：2026-05-26-tz-mall-design.md 设计文档
> 当前项目进度：约 20-25%（第一阶段中期）

---

## 一、当前进度概览

### 已完成
- Maven 多模块骨架（14 个子模块）
- common-core：`Result` 统一响应封装
- user-service：完整 CRUD + 注册登录（Controller/Service/Mapper/Entity）
- item-service：基本 CRUD（缺启动类）
- gateway：基础路由 + Nacos 注册/配置中心
- 数据库初始化脚本（user, item, order, order_detail）
- api-user（3 个 DTO）、api-item（2 个 DTO）

### 未完成
- common-redis / common-mq / common-es / common-swagger：仅有骨架
- api-order：空白
- order-service：空白
- item-service：缺启动类
- gateway：路由服务名不匹配，无鉴权/限流/跨域
- JWT 认证、Feign 客户端、Redis 缓存、RabbitMQ、ES 搜索、Sentinel、Seata：均未实现

## 二、耦合度分层模型

| 层级 | 名称 | 特征 | 涉及模块 |
|------|------|------|---------|
| **L0** | 零耦合 | 单模块内部完善，不依赖其他服务或中间件 | common-core、common-swagger、item-service 启动类、gateway 路由修复 |
| **L1** | 基础设施耦合 | 单模块 + 单个中间件，不涉及服务间调用 | common-redis、common-mq、common-es、Docker Compose |
| **L2** | 单服务内耦合 | 一个服务内整合多个技术点 | user-service + JWT + Redis、item-service + Redis + ES + Sentinel |
| **L3** | 服务间耦合 | 涉及 Feign 远程调用，两个以上服务协作 | api-order、Feign 客户端、order-service 搭建、三服务联调 |
| **L4** | 高耦合 | 跨服务 + 多中间件 + 分布式事务 | Seata 分布式事务、RabbitMQ 延迟队列、Gateway 统一鉴权限流 |

## 三、详细工作计划

### L0 - 零耦合：基础补全（预计 0.5-1 天）

| 序号 | 任务 | 说明 | 验证标准 |
|------|------|------|---------|
| 0.1 | common-core 补全 | 添加 `GlobalExceptionHandler`、自定义业务异常类 `BizException` | 异常可被全局捕获并返回统一格式 |
| 0.2 | common-swagger 配置 | 添加 Knife4j/OpenAPI 配置类 | 访问 Knife4j UI 可看到 API 文档 |
| 0.3 | item-service 启动类 | 创建 `ItemApplication.java` | item-service 可独立启动并注册到 Nacos |
| 0.4 | gateway 路由修复 | 修正服务名映射，添加跨域配置 | Gateway 可正确路由到 user-service 和 item-service |
| 0.5 | 三服务启动验证 | 确保 user/item/gateway 均正常启动 | Nacos 控制台可见 3 个服务注册 |

### L1 - 基础设施耦合：中间件配置（预计 1-1.5 天）

| 序号 | 任务 | 说明 | 验证标准 |
|------|------|------|---------|
| 1.1 | Docker Compose 编排 | 创建 docker-compose.yml（Nacos + RabbitMQ + ES + Sentinel） | docker-compose up 一键启动所有中间件 |
| 1.2 | common-redis 配置 | Redis 连接配置类、RedisTemplate 序列化、工具类封装 | 可通过工具类读写 Redis |
| 1.3 | common-mq 配置 | RabbitMQ 连接配置、JSON 序列化、通用消息工具类 | 可发送和接收测试消息 |
| 1.4 | common-es 配置 | ES 客户端配置类、索引操作工具类 | 可连接 ES 并执行索引操作 |

### L2 - 单服务内耦合：技术点集成（预计 2-3 天）

| 序号 | 任务 | 说明 | 验证标准 |
|------|------|------|---------|
| 2.1 | user-service + JWT + Redis | 登录生成 JWT Token，存入 Redis，Token 验证拦截器 | 登录返回 Token，携带 Token 可访问受保护接口 |
| 2.2 | item-service + Redis 缓存 | 商品详情缓存（穿透/击穿/雪崩防护），库存扣减接口 | 商品查询命中缓存，库存可正确扣减 |
| 2.3 | item-service + ES 搜索 | 商品数据同步 ES，全文搜索 + 高亮显示 | 搜索接口返回匹配结果并高亮关键词 |
| 2.4 | item-service + Sentinel 限流 | 热点商品查询限流、接口熔断降级 | 高并发下触发限流返回降级响应 |

### L3 - 服务间耦合：Feign 互通 + 订单服务（预计 2-3 天）

| 序号 | 任务 | 说明 | 验证标准 |
|------|------|------|---------|
| 3.1 | api-order 模块补全 | 定义 OrderDTO、OrderDetailDTO、CreateOrderDTO 等 | DTO 定义完整，校验注解齐全 |
| 3.2 | Feign 客户端定义 | api-user/api-item/api-order 中定义 Feign 接口 | Feign 接口可被其他服务引用 |
| 3.3 | order-service 完整搭建 | Entity/Mapper/Service/Controller 全链路 | 订单 CRUD 接口可用 |
| 3.4 | 三服务联调 | order-service 通过 Feign 调用 user/item 服务 | 创建订单时正确查询用户和商品信息 |

### L4 - 高耦合：分布式事务 + 消息队列 + 网关增强（预计 2-3 天）

| 序号 | 任务 | 说明 | 验证标准 |
|------|------|------|---------|
| 4.1 | Seata 分布式事务 | 下单时 order + item 库存扣减 AT 模式事务 | 事务失败时数据回滚一致 |
| 4.2 | RabbitMQ 延迟队列 | 订单超时取消：延迟消息 → 超时自动取消 → 回滚库存 | 超时未支付订单自动取消 |
| 4.3 | Gateway 统一鉴权 | 全局 JWT Token 校验过滤器，白名单放行 | 未携带 Token 请求被拦截 |
| 4.4 | Gateway 限流 | Sentinel 集成 Gateway，请求限流规则 | 超过阈值返回 429 |
| 4.5 | 全局联调测试 | 完整流程：注册→登录→浏览→下单→支付/超时取消 | 完整业务闭环可用 |

## 四、时间线

```
L0 基础补全 ──→ L1 中间件配置 ──→ L2 技术点集成 ──→ L3 服务间耦合 ──→ L4 高耦合集成
  0.5-1天         1-1.5天          2-3天             2-3天             2-3天
                                                              总计: 8-12天
```

---

## 五、执行原则

1. **逐层推进**：每层完成并验证通过后，才进入下一层
2. **每层可独立验证**：不依赖上层功能即可测试当前层成果
3. **出现问题回退成本低**：低耦合任务失败不影响已完成的高耦合功能
4. **渐进式集成**：从简单到复杂，每一步都在上一步基础上叠加
